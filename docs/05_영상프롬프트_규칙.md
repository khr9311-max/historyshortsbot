# 영상 프롬프트 설계 규칙

> `docs/02_스타일_바이블.md`의 하위 문서.
> **프롬프트를 만들 때는 반드시 `docs/06_골든_프롬프트.md`를 함께 참조한다.**
> 규칙보다 예시가 우선이다.

---

## 0. 가장 중요한 원칙

**규칙을 나열하지 말고, 검증된 프롬프트를 예시로 붙여라.**

새 프롬프트를 만들 때는 같은 패턴의 골든 프롬프트를 첨부하고
**"이 프롬프트의 어휘와 길이를 그대로 따르되 내용만 바꿔라"**로 요청한다.

규칙 기반 생성은 매번 다른 결과를 낸다. 예시 기반 생성은 복제된다.
채널 일관성은 여기서 나온다.

## 1. 컷 타입

| 타입 | scenes.json `kind` | 내부 코드 | 편당 | 내용 | 제작 |
|---|---|---|---|---|---|
| 영상 컷 | `veo` | `ai_hero` | 6컷 | 현장·사회·계측 연출 | Veo 3.1 Lite t2v 8초, 2비트 |
| 정지 컷 | `still` | `ai_still` | 1컷 | 분위기 정지 + 슬로우 줌 | 이미지 → zoompan |
| 도해 컷 | `diagram` | `diagram` | 3컷 | 한글 라벨·인과도·타임라인·그래프 | Manim 투명 렌더 → 플레이트 합성 |

편당 10컷 / 유료 생성 3회(서사 클립). 도해의 배경 플레이트는 전역 자산이라 0원이다.

`scenes.json`에는 `veo`/`still`/`diagram`만 쓴다. `ai_hero`/`ai_still`은
`scenes.tsv`와 `timing.json`으로 넘어갈 때 자동 변환되는 내부 이름이다.

### `veo`에 맡겨도 되는 것
- 빨간 계측선 (red measurement lines)
- 아라비아 숫자 (`7cm`, `1750`, `+300%`)
- 단순 지시 화살표, 하이라이트 링
- **영어 전문용어 라벨** (`LOAD PATH`, `SINGLE TRACK`) — 단어 수는 최소로

영어 라벨은 모델이 잘 그린다. 한글만 못 그린다.
그래서 화면 위 정보는 **영어 전문용어**로 밀어 넣고, 설명은 자막과 도해가 맡는다.
이렇게 나누면 AI 컷도 정보를 실어 나를 수 있다.

### 반드시 `diagram`으로
- 한글이 한 글자라도 들어가는 화면
- 인과 다이어그램, 타임라인, 그래프, 지도 경로, 픽토그램 비교

**애매하면 `diagram`.** 재생성 비용 > Manim 작성 시간.

### 도해의 배경은 플레이트가 맡는다

도해 컷은 알파 채널로 렌더돼 `assets_global/plates/` 의 8초 추상 루프 위에 얹힌다.
**그래서 도해 컷도 배경이 움직인다.** 편당 10컷 중 정지 톤인 컷은 `still` 하나뿐이다.

플레이트는 `shots` 에 넣지 않는다 — 에피소드 자산이 아니라 전역 자산이고,
프롬프트를 쓸 일도 없다. 씬 쪽에서 `plate` 로 어느 루프를 쓸지만 고른다.

```json
{"id": "S03", "kind": "diagram", "plate": "fog", "pause": 0.34, ...}
```

| `plate` | 파일 | 쓰는 자리 |
|---|---|---|
| `fog` | `P_fog.mp4` | 인과 다이어그램 · 통념 부정 |
| `dust` | `P_dust.mp4` | 타임라인 · 연표 |
| `grid` | `P_grid.mp4` | 그래프 · 수치 컷 |

생략하면 `fog`. 한 에피소드에서 셋을 다 쓰지 않아도 된다.

## 2. 2비트 = 씬 두 개 ★ 이 프로젝트의 재설계 지점

8초 클립 하나에 최대 2개 비트를 넣는다. 그리고 **그 두 비트는 씬 두 개다.**

```
V01 (8초 t2v 클립 = 유료 생성 1회)
  ├── S01  beat A  side_track   나레이션 3.84초
  └── S02  beat B  push_in      나레이션 2.99초
                                 ─────────────
                                 합계 6.83초 ≤ 8초
```

씬 두 개가 클립을 **연속으로 소진**한다. `build.py`가 비트 A는 `[0, 3.84]`,
비트 B는 `[3.84, 6.83]` 구간을 잘라 쓴다. 버려지는 구간이 없고,
컷 전환이 비트 전환과 정확히 같은 지점에서 일어난다.

### 비트 경계는 대본이 정한다

프롬프트의 `[0-5s]` / `[5-8s]`는 **작성 시점의 임시값**이다.
TTS 실측이 나오면 `pipeline.py prompt` 단계가 자동으로 갈아끼운다.

```
작성:  [0-5s] … [5-8s] …
확정:  [0-3.8s] … [3.8-8s] …   → prompts/V01.txt
```

그래서 "8초 2비트"와 "나레이션이 컷 길이를 정한다"가 충돌하지 않는다.
**프롬프트에 손으로 초를 적어 넣지 마라.** 토큰 형식만 지키면 된다.

### 7초 룰

두 씬의 길이 합(정지 구간 포함)이 8초를 넘으면 파이프라인이 멈춘다.
정지 구간이 0.4초씩 들어가므로 **실제 발화는 두 문장 합쳐 7초 이내**여야 한다.
한국어로 대략 **두 문장, 합쳐 45자 안팎**이다.

```
S01  "기술이 가장 앞섰던 나라는 영국이 아니었습니다."   (22자 → 3.4초)
S02  "그런데 왜 영국에서만 폭발했을까요?"               (18자 → 2.5초)
```

넘치면 대본을 줄이거나, 씬 하나를 `diagram`으로 돌린다.
`diagram`은 0원이므로 길이 압박은 항상 도해 쪽으로 흘려보낸다.

### 1비트 클립

`scenes` 배열에 씬을 하나만 넣으면 1비트 클립이 된다. 허용되지만
8초를 사서 4초만 쓰는 셈이라 경고가 뜬다. 훅 컷처럼 값이 확실한 자리에만 쓴다.

## 3. 카메라 워크 (계열별 고정)

무빙을 고르는 게 아니다. **계열을 고르면 무빙이 따라온다.**

| 계열 | 비트 A (상황을 연다) | 비트 B (파고든다) |
|---|---|---|
| **A · 다큐멘터리 실루엣** | `side_track` 좌우 횡이동 | `push_in` 급속 푸시인 |
| **B · 아이소메트릭 디오라마** | `dolly_out` 단면에서 전체로 | `zoom_in` 내부 구획으로 |

- 비트 A에서 확대·크레인을 쓰지 않는다. 여는 동작만 한다
- 비트 B는 클립 끝 2~3초. 항상 파고드는 방향이다
- **한 클립 안에서 계열을 섞지 않는다.** `lib_scenes` 가 오류로 막는다
- 에피소드 단위로 계열 하나만 쓴다. 섞으면 두 채널을 번갈아 보는 느낌이 난다

계열 선택 기준과 공통 앵커는 `docs/06_골든_프롬프트.md` 를 본다.
구조물·기계·경로처럼 **보이는 대상**이면 B, 제도·시장·관념이면 A다.

### 바이블 §5 무브 3종과의 관계

`dolly_in` / `orbit` / `crane_up`은 **정지 컷(`still`) 전용**이다.
FFmpeg zoompan이 만드는 가짜 무빙이라 파라미터가 다르다.
`veo` 컷은 위 표의 넷만 쓴다. 파이프라인이 이를 강제한다.

## 4. 프롬프트 고정 블록

계열마다 앵커가 다르다. 아래는 **A 계열(다큐멘터리 실루엣)** 것이다.
B 계열(아이소메트릭 디오라마) 앵커는 `docs/06_골든_프롬프트.md` 에 있다.
**앵커는 한 글자도 바꾸지 않는다.** 톤 통일이 전부 여기서 나온다.

```
, cinematic documentary footage, deep navy blue tone, low saturation,
single directional light, heavy atmospheric haze,
red measurement lines and numeric annotations overlaid,
silhouette figures only, no visible faces, no Korean text,
subtle film grain, 9:16 vertical, 8 seconds
```

### 네거티브
```
korean text, hangul, garbled letters, close-up faces, hands,
modern logos, watermark, oversaturated, cartoon, cluttered
```

### 길이 규칙
골든 프롬프트의 **글자 수 ±15% 이내**를 유지한다.
너무 짧으면 디테일이 빠지고, 너무 길면 모델이 지시를 버린다.
`chars` 필드에 글자 수를 적으면 실제 길이와 대조해 준다.

## 5. 실패 리스크 사전 태깅 (필수)

씬마다 렌더 실패 위험을 판정해 `scenes.json`의 `risk`에 기록한다.

| 리스크 | 신호 | 대응 |
|---|---|---|
| `high` | 비트끼리 장소가 다름 / 얼굴 클로즈업 / 한글 표기 / 군중+물+불 복합 | 씬 분할 또는 `diagram` 전환 |
| `mid` | 물·불 물리 시뮬 / 숫자 3개 이상 / 복잡한 구조물 | 비트 1개로 축소 |
| `low` | 단일 공간, 단순 피사체, 느린 횡이동 | 진행 |

**`risk: high`는 파이프라인이 `script` 단계에서 멈춘다.** 경고가 아니라 오류다.
돈이 나가기 전에 멈추는 게 이 태깅의 목적이다.

장소가 서로 다른 비트를 한 클립에 묶으면 톤이 무너진다. 두 클립으로 쪼갠다.

## 6. scenes.json 스키마

`episodes/<EP>/scenes.json`이 대본·씬 분해·프롬프트의 **단일 권원**이다.

```json
{
  "episode": "EP007",
  "title": "왜 영국에서만 폭발했나",
  "shots": [
    {
      "id": "V01",
      "kind": "veo",
      "scenes": ["S01", "S02"],
      "prompt": "[0-5s] … [5-8s] … (고정 블록 포함, 영문)",
      "chars": 412,
      "risk": "low",
      "golden_ref": "GP-01"
    },
    {
      "id": "I01",
      "kind": "still",
      "scenes": ["S05"],
      "prompt": "(영문 전체 프롬프트)",
      "chars": 260,
      "risk": "low",
      "golden_ref": "GP-05"
    }
  ],
  "scenes": [
    {"id": "S01", "shot": "V01", "beat": "A", "move": "side_track", "pause": 0.42,
     "note": "도입 훅",
     "narration": "기술이 가장 앞섰던 나라는 영국이 아니었습니다.",
     "subs": ["기술이 가장 앞섰던 나라는", "*영국이 아니었습니다.*"]},

    {"id": "S03", "kind": "diagram", "pause": 0.34,
     "note": "도해 - 통념 부정",
     "narration": "천재가 나타나서도, 운이 좋아서도 아닙니다.",
     "subs": ["천재가 나타나서도,", "*운이 좋아서도 아닙니다.*"]}
  ]
}
```

### 필드

**shots** — 돈이 나가는 생성 단위. API 호출 한 번.

| 필드 | 값 |
|---|---|
| `id` | `V01`, `V02`… (veo) / `I01`, `I02`… (still) |
| `kind` | `veo` \| `still` |
| `scenes` | 이 샷이 채우는 씬. veo는 1~2개, still은 1개. **연속된 씬이어야 한다** |
| `prompt` | 영문 전체 프롬프트. 한글이 들어가면 오류 |
| `chars` | 프롬프트 글자 수 |
| `risk` | `low` \| `mid` \| `high` |
| `golden_ref` | 근거로 삼은 골든 프롬프트 ID |

**scenes** — 나레이션 한 덩어리 = 컷 하나.

| 필드 | 값 |
|---|---|
| `id` | `S01`… |
| `shot` | 이 씬을 채우는 샷 id. `diagram`이면 쓰지 않는다 |
| `kind` | `diagram`일 때만 명시. 나머지는 샷에서 자동으로 온다 |
| `plate` | `diagram`일 때만. `fog`\|`dust`\|`grid`. 생략하면 `fog` |
| `beat` | veo 2비트일 때 `A` / `B` |
| `move` | veo A → `side_track`\|`dolly_out` · veo B → `push_in`\|`zoom_in` · still → `dolly_in`\|`orbit`\|`crane_up` |
| `narration` | 나레이션 원문. **이 길이가 컷 길이를 정한다** |
| `subs` | 화면 자막. `*별표*`가 ACCENT. 한 컷 최대 2줄, 강조는 한 곳만 |
| `pause` | 이 문장 뒤 정지 길이(초). 컷 전환이 여기서 일어난다 |
| `note` | 사람이 읽는 메모 |

**`dur`은 쓰지 않는다.** TTS 실측으로 자동 결정된다.

### 배치 규칙 (파이프라인이 검사한다)

- 1번 씬은 `veo`
- `diagram` 3연속 금지
- **`diagram` 3~4컷 권장** (서사 클립 3개 = `veo` 6컷이 기준선)
- **`still` 1컷** — 두 장 이상 넣으면 정지 톤이 겹친다
- 마지막 컷은 요약 도해 + 루프백

컷 수가 부족하면 `diagram` 이 아니라 **`veo` 클립을 하나 더** 잡는 게 맞다.
Lite 기준 900원이고, 도해를 4컷 넘게 쌓는 것보다 체감 차이가 크다.
다만 편당 4클립을 넘기면 월 예산에서 재시도분이 사라진다.

## 7. 부분 수정

전체를 다시 뽑지 말고 **해당 샷만** 수정한다.

수정 요청 형식:
```
V02 프롬프트만 수정. 나머지는 그대로.
- 배경의 강과 전경이 더 뚜렷하게 보이도록 안개 조정
- "7cm" 계측 수치를 화면에 한 번 더 시각적으로 표기
```

파이프라인에서 해당 샷만 재처리:
```bash
python scripts/pipeline.py EP007 --from prompt --to video --only V02
```

생성물을 새로 받으면 `assets/clips/V02.mp4`를 덮어쓰고 다시 조립한다.
`--only`는 완료 표시를 무시하므로 `--force` 없이 바로 돈다.

## 8. claude.ai 프로젝트 지침에 추가할 문장

```
• 씬 분해는 scenes.json 형식으로 출력한다.
   - shots(생성 단위)와 scenes(나레이션 단위)를 나눠서 쓴다
   - veo 샷 하나는 씬 두 개를 채운다 (beat A 가 열고, beat B 가 파고든다)
   - 계열을 먼저 고른다. 보이는 대상이면 B(디오라마), 관념이면 A(다큐멘터리)
       A 계열 무브: beat A = side_track / beat B = push_in
       B 계열 무브: beat A = dolly_out  / beat B = zoom_in
     한 에피소드 안에서 계열을 섞지 않는다
   - 한 veo 샷이 채우는 두 씬의 나레이션은 합쳐 7초(45자) 이내로 쓴다
   - 한글 텍스트가 필요한 화면은 무조건 diagram
   - 컷 배분은 veo 6컷(서사 클립 3개) / still 1컷 / diagram 3컷 = 총 10컷
   - diagram 씬에는 plate(fog|dust|grid)를 골라 적는다. 배경은 전역 자산이라 무료다
   - 프롬프트는 첨부한 골든 프롬프트의 어휘와 길이를 그대로 따를 것
   - 프롬프트의 비트 표기는 [0-5s] / [5-8s] 형식만 지키면 된다
     (실제 초는 TTS 실측으로 자동 교체된다)
   - 각 샷에 risk(low/mid/high)와 글자 수를 기록
   - dur은 쓰지 않는다
   - 대본 문체는 docs/07_대본_문체_규칙.md 를 따른다
     (역설적 오프닝 · 어미 리듬 교차 · 셀프 문답)
```
