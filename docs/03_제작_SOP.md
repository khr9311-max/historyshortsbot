# 제작 SOP — 역사 인과 쇼츠 (주 3편)

---

## 1. 스펙

| 항목 | 값 |
|---|---|
| 포맷 | 9:16, 1080×1920, 25fps |
| 길이 | 45~55초 |
| 씬 수 | 10씬 |
| 컷 배분 | `veo` 6 / `still` 1 / `diagram` 3 |
| 유료 생성 | **샷 4개** (veo 클립 3 + still 이미지 1) |
| 영상 모델 | Veo 3.1 Lite 1080p ($0.08/s → 8초 ≈ 900원) |
| 발행 | 주 3편 (월/수/금 예약) |

씬 수와 생성 횟수가 다르다. **veo 클립 하나가 씬 두 개를 채운다** (규칙 §2).
veo 컷이 6개라도 돈이 나가는 건 클립 3개다. 여기가 이 파이프라인의 절약 지점이다.

도해 3컷의 배경은 `assets_global/plates/` 의 전역 루프를 재사용하므로 0원이다.
**정지 톤인 컷은 `still` 하나뿐이다.**

## 2. 파이프라인

```
소재 큐 → [claude.ai 프로젝트] 대본·씬분해·프롬프트 → scenes.json
            ↓
        [pipeline.py] script → sources(GATE1) → narration
            ↓                                      ↓
        prompts/*.txt (비트 경계 확정)      vo.wav·sub.ass·scenes.tsv·timing.json
            ↓
        t2v 클립 3개 (Gemini API, pipeline.py video 단계 자동) ┐
        정지 이미지 1장 생성 (사람이 실행) ────────────────────┤
        Manim 도해 3컷 + 플레이트 합성 (0원) ──────────────────┤
            ↓                                          ↓
        [pipeline.py] video → diagram → assemble → review(GATE2) → 업로드
```

**역할 분담**
- **claude.ai 프로젝트** = 소재·대본·씬 분해·프롬프트·출처 → `scenes.json` 하나로 출력
- **Claude Code** = Manim 씬 코드·파이프라인·조립·QC
- **`pipeline.py`** = veo 클립 생성(Gemini API, `video` 단계에서 자동 호출)
- **사람** = still 이미지 생성, GATE1·GATE2 판단, 업로드

`pipeline.py`는 이미 파일이 있는 샷은 절대 다시 부르지 않는다 — 재실행으로
과금이 중복되는 사고를 막는 유일한 장치다. 다시 뽑고 싶으면
`assets/clips/<샷ID>.mp4` 를 직접 지우고 재실행한다. 레포 루트 `.env` 에
`GEMINI_API_KEY=...` 한 줄이 필요하다 (`.gitignore` 대상, 커밋되지 않는다).

## 3. 주간 루틴 (총 5~6시간)

| 요일 | 작업 | 소요 |
|---|---|---|
| 일 | 소재 3개 → 대본 3편 + scenes.json 작성 + 출처 확인 | 110분 |
| 월 | `pipeline.py` 3편 (검증→나레이션→prompts) + 프롬프트 검수 | 30분 |
| 화 | t2v 클립 6개 + 이미지 3~6장 생성·선별 | 50분 |
| 수 | Claude Code로 Manim 도해 12~15컷 작성·렌더 | 90분 |
| 목 | 조립 3편 + qc 검수 + 예약 업로드 | 60분 |

**원칙: 절대 1편씩 만들지 않는다.** 공정 단위로 3편을 한 번에.

월요일에 프롬프트를 먼저 확정하는 게 중요하다. 나레이션 실측이 나와야
비트 경계가 정해지고, 그래야 화요일에 클립을 한 번에 뽑을 수 있다.

Manim 도해는 회차가 쌓일수록 빨라진다. 5회차쯤이면 기존 씬을 복사·수정하는
수준이 되어 90분 → 40분으로 줄어든다.

## 4. 월 예산 (12편)

t2v 전면 전환으로 **영상비가 예산 전체를 좌우한다.** 다른 항목은 사실상 0이다.

| 항목 | 수량 | 예상 |
|---|---|---|
| t2v 클립 (Veo 3.1 Lite 1080p, 8초) | 36클립 | **32,400원** |
| AI 이미지 | 12장 | 1,000원 |
| TTS (edge-tts 로컬) | 12편 | **0원** |
| Manim 도해 | 36컷 | **0원** |
| 배경 플레이트 | 전역 재사용 | **0원** |
| 편집·BGM | — | 0원 |
| **합계** | | **약 33,400원** (예산 한도 10만원) |

### 모델 선택 근거

8초 1080×1920 클립 1개 단가 (₩1,400/$ 가정), **재시도 계수 1.5배 포함**:

| 모델 | 단가/초 | 클립 1개 | 월 36클립 ×1.5 | 판정 |
|---|---|---|---|---|
| Veo 3.1 Standard | $0.40 | 4,500원 | 243,000원 | **불가** |
| Veo 3.1 Fast | $0.12 | 1,350원 | 72,900원 | 예산 안 — 화질 업그레이드 후보 |
| **Veo 3.1 Lite** | **$0.08** | **900원** | **48,600원** | **채택** |
| Gemini Omni Flash (720p) | ~$0.10 | 1,100원 | 59,400원 | 업스케일 필요 |

t2v는 한 번에 안 나온다. 위 금액은 이미 그 재시도분을 반영한 값이다.
예산이 10만원으로 오르면서 Lite(48,600원)는 절반 이상 여유가 남고,
Fast(72,900원)도 예산 안에 들어온다 — Lite 화질에 불만이 생기면
재작업 없이 Fast로 갈아탈 수 있다.

Omni Flash는 subject reference(클립 간 톤 고정)와 대화형 재편집이 있어
일관성 면에서 낫지만 720p라 업스케일이 붙는다.

### 초과 시 줄이는 순서

1. Veo 3.1 Lite → Fast/Standard 로 올렸다면 먼저 Lite 로 되돌린다
2. 편당 veo 클립 3개 → **2개** (월 24클립). 빈 자리는 `diagram` 으로
3. 발행 주 3편 → **주 2편**
4. 훅 컷만 veo, 나머지 전부 `still` + `diagram`

**도해를 줄이는 선택지는 없다.** 도해는 0원이면서 이 채널의 정체성이다.
길이 압박도 비용 압박도 전부 도해 쪽으로 흘려보낸다.

## 5. 발행 전 QC 체크리스트

**구조**
- [ ] 4파트(도입/난관/해결/요약)가 명확히 구분되는가
- [ ] 1번 씬이 `veo`인가
- [ ] `diagram` 컷이 3개 연속으로 붙어 있지 않은가
- [ ] 마지막 컷이 요약 도해인가
- [ ] veo 2비트 페어가 8초 안에 들어갔는가 (파이프라인이 자동 검사)

**시각**
- [ ] AI 컷에 한글·숫자가 노출된 곳이 없는가
- [ ] 비트 A가 횡이동, 비트 B가 푸시인인가
- [ ] 비트 전환 지점이 컷 전환과 어긋나 보이지 않는가
- [ ] 한 화면에 `ACCENT`가 한 곳만 쓰였는가
- [ ] 후처리 3종이 모든 컷(도해 포함)에 적용됐는가

**내용**
- [ ] 단일 원인 설명이 되어버린 구간이 없는가
- [ ] 논쟁 사안에 학설 구분이 표기됐는가
- [ ] `sources.md`의 모든 수치·연도에 근거가 있는가
- [ ] 특정 집단의 우열을 함의하는 표현이 없는가

**발행**
- [ ] AI 생성 콘텐츠 라벨 체크
- [ ] 자막 2줄 이내

`./scripts/qc.sh EP007`로 기계적 항목은 자동 검사된다. 내용 항목은 눈으로 본다.

## 6. 프로덕션 시트 컬럼

`ep_id / 상태 / 소재 / 인과구조요약 / 출처확인 / 훅안 / 씬수 / diagram수 / 렌더상태 / 업로드일 / 조회수 / 시청지속률 / 평균시청시간`
